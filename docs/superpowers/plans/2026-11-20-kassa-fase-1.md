# Kassa Burcht ter Cleeff, Fase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working till web app (kassa screen for the iPad, beheer for the penningmeester) with cash sales, cash-box control, reports, product management and ice-cream stock, deployed on Cloudflare. No card payments yet.

**Architecture:** One Cloudflare Worker serves a React SPA as static assets and a Hono JSON API under `/api/*`, with all data in D1. The kassa is local-first: the catalog and an outbox of sales live in IndexedDB on the iPad, and the server accepts each sale id exactly once. A reversal is a counter-entry (a new sale row with negative amounts); a handover closes a cash period.

**Tech Stack:** TypeScript, React 19, React Router, Tailwind 4, Vite 8 with `@cloudflare/vite-plugin`, Hono, D1, zod 4, `idb`, `vite-plugin-pwa`, Vitest (`@cloudflare/vitest-plugin` for Worker tests; jsdom + Testing Library + `fake-indexeddb` for client tests), Playwright (WebKit).

**Spec:** `docs/superpowers/specs/2026-11-20-kassa-design.md` (Dutch). Screen behaviour reference: `.superpowers/brainstorm/8477-1795168180/content/kassa-scherm.html`, variant A.

**Scope:** Fase 1 of spec §13 only. Fase 2 (pin via Mollie), ingebruikname and Moneybird get their own plans. Where fase 2 will need a hook (sale `method` `pin`, `status` `pending`/`failed`), the schema already allows it, but no fase 2 code is written here. Left for fase 2, although spec §8 and §9 describe them: the Pin dialog, the `TEST` bar, the mark `mogelijk dubbel betaald`, and choosing the Mollie terminal in Instellingen.

## Global Constraints

- All UI copy is Dutch. Error codes in API responses are English `snake_case`; the UI maps them to Dutch.
- Money is integer cents everywhere in code, storage and API. Display format is `€ 1,10` (euro sign, non-breaking space, decimal comma). No VAT anywhere.
- Business dates and months follow `Europe/Amsterdam`. Timestamps are stored as UTC ISO 8601 strings from `Date.prototype.toISOString()`.
- A sale id (client-generated UUID) is accepted exactly once, however often it is sent.
- Cart operations on the kassa never wait on the network. Cash sales work offline.
- No secrets in the repository or in client code. `.dev.vars` is gitignored. Passwords and tokens are stored hashed only.
- Target browser: current Safari on a two-year-old iPad, landscape, 1180×820 CSS px. Touch targets at least 44×44 px. No support for older browsers.
- House style tokens (exact): font DM Sans (weights 400 and 600, bundled); ink `#252628`; cream `#F3EEE2`; green `#78992B`; red-brown `#853F21`; sand `#E0E1DA`. Pill-shaped buttons. White text on `#78992B` only at 18 px bold or larger; smaller text uses `#566E1F`.
- Cloudflare free tier only: Workers and D1.
- Package manager npm, Node 24, all packages at latest. `@cloudflare/vitest-plugin` 1.8 accepts `vitest` `^4.1.0 || ^5.0.0`; if the latest Vitest misbehaves under workerd, fall back to `vitest@^4.1.0`.
- Commit after every task, locally, on branch `main`. Never push; there is no remote.
- Worker tests share storage within a test file (isolation is per file). Every Worker test file calls `resetData()` in `beforeEach`.

## Review Focus

Conditions the spec implies but does not spell out, most likely first. Each has a pinning test in the task named.

1. **A sale around midnight or on a clock-change day** lands on the Amsterdam calendar day it was made, not the UTC day. Tasks 2 and 7.
2. **One bad item in the outbox** (rejected by the server) must not block every later sale from syncing; it is set aside and reported. Tasks 7 and 14.
3. **A stale iPad** (price changed or product hidden in beheer after the cart was filled, or while offline): the sale is accepted at the price the customer saw. Task 7.
4. **A double tap** on Gepast, Klaar or Ontvangen records one sale or one delivery. Tasks 9, 13 and 15.
5. **A device that was unpaired while it still holds unsent sales** keeps them, says so, and sends them after pairing again. Task 14.

```sql
-- migrations/0001_init.sql
CREATE TABLE categories (id TEXT PRIMARY KEY, name TEXT NOT NULL, color TEXT NOT NULL, sort INTEGER NOT NULL);
CREATE TABLE products (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, price_cents INTEGER NOT NULL CHECK (price_cents >= 0),
  category_id TEXT NOT NULL REFERENCES categories(id), sort INTEGER NOT NULL,
  active INTEGER NOT NULL DEFAULT 1, quantity_pad INTEGER NOT NULL DEFAULT 0,
  track_stock INTEGER NOT NULL DEFAULT 0, units_per_box INTEGER, reorder_at INTEGER, updated_at TEXT NOT NULL);
CREATE TABLE devices (id TEXT PRIMARY KEY, name TEXT NOT NULL, token_hash TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL, last_seen_at TEXT, revoked_at TEXT);
CREATE TABLE handovers (
  id TEXT PRIMARY KEY, kind TEXT NOT NULL CHECK (kind IN ('opening','handover')), counted_at TEXT NOT NULL,
  expected_cents INTEGER NOT NULL, received_cents INTEGER NOT NULL, left_cents INTEGER NOT NULL,
  difference_cents INTEGER NOT NULL, note TEXT, created_at TEXT NOT NULL);
CREATE TABLE sales (
  id TEXT PRIMARY KEY, device_id TEXT REFERENCES devices(id),
  method TEXT NOT NULL CHECK (method IN ('cash','pin')),
  status TEXT NOT NULL DEFAULT 'paid' CHECK (status IN ('paid','pending','failed')),
  total_cents INTEGER NOT NULL, cash_given_cents INTEGER,
  sold_at TEXT NOT NULL, received_at TEXT NOT NULL, business_date TEXT NOT NULL,
  reverses_sale_id TEXT REFERENCES sales(id), reversal_reason TEXT,
  reversed_by TEXT CHECK (reversed_by IN ('device','admin')),
  late INTEGER NOT NULL DEFAULT 0, handover_id TEXT REFERENCES handovers(id));
CREATE UNIQUE INDEX sales_one_reversal ON sales(reverses_sale_id) WHERE reverses_sale_id IS NOT NULL;
CREATE INDEX sales_by_date ON sales(business_date);
CREATE TABLE sale_lines (
  id INTEGER PRIMARY KEY AUTOINCREMENT, sale_id TEXT NOT NULL REFERENCES sales(id) ON DELETE CASCADE,
  product_id TEXT NOT NULL, name TEXT NOT NULL, category_id TEXT NOT NULL, category_name TEXT NOT NULL,
  unit_price_cents INTEGER NOT NULL, qty INTEGER NOT NULL);
CREATE INDEX sale_lines_by_sale ON sale_lines(sale_id);
CREATE TABLE stock_orders (id TEXT PRIMARY KEY, status TEXT NOT NULL CHECK (status IN ('open','received','cancelled')),
  note TEXT, created_at TEXT NOT NULL, received_at TEXT, received_by TEXT CHECK (received_by IN ('device','admin')));
CREATE TABLE stock_order_lines (id INTEGER PRIMARY KEY AUTOINCREMENT,
  order_id TEXT NOT NULL REFERENCES stock_orders(id) ON DELETE CASCADE,
  product_id TEXT NOT NULL REFERENCES products(id), boxes INTEGER NOT NULL DEFAULT 0,
  loose_units INTEGER NOT NULL DEFAULT 0, units INTEGER NOT NULL CHECK (units > 0));
CREATE TABLE stock_movements (id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id TEXT NOT NULL REFERENCES products(id), delta INTEGER NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('delivery','sale','reversal','count')),
  ref_id TEXT, note TEXT, created_at TEXT NOT NULL);
CREATE INDEX stock_movements_by_product ON stock_movements(product_id);
CREATE TABLE admin (id INTEGER PRIMARY KEY CHECK (id = 1), password_hash TEXT NOT NULL, salt TEXT NOT NULL,
  iterations INTEGER NOT NULL, updated_at TEXT NOT NULL);
```

CSV, `kind=days`, filename `kassa-YYYY-MM-dagen.csv`: header `datum;contant;pin;totaal;aantal_verkopen` followed by one column per category name in `sort` order; one row per day in `MonthReport.days`; a final row with `totaal` in the first column. Amounts via `formatAmount`, dates via `formatDateNl`.
CSV, `kind=sales`, filename `kassa-YYYY-MM-verkopen.csv`: header `datum;tijd;bon;betaalwijze;product;categorie;aantal;stukprijs;regeltotaal;teruggedraaid_van`; one row per sale line, ordered by `sold_at`; `bon` is the first 8 characters of the sale id; `betaalwijze` is `contant` or `pin`; `teruggedraaid_van` is the first 8 characters of `reverses_sale_id` or empty.
Response headers: `Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="<name>"`.

### Task 14: The kassa's memory: outbox, catalog cache, pairing, last-sale reversal

**Files:**
- Create: `src/kassa/store/db.ts`, `src/kassa/store/outbox.ts`, `src/kassa/store/catalog.ts`, `src/kassa/store/sync.ts`, `src/kassa/KassaPage.tsx`, `src/kassa/PairPage.tsx`, `src/kassa/StatusBadge.tsx`, `src/kassa/LastSaleBar.tsx`

**Interfaces:**
- Consumes: `KassaScreen`, `kassaApi`, `OutboxItem`, `ItemResult`, `Catalog`.
- Produces, `src/kassa/store/db.ts`: `getDb(): Promise<IDBPDatabase>`, database `kassa` version 1 with stores `outbox` (key `seq`, auto-increment; value `{ seq, item: OutboxItem }`), `rejected` (key `id`; value `{ id, item, reason, at }`) and `meta` (key-value); `getMeta<T>(key: string): Promise<T | undefined>`, `setMeta(key: string, value: unknown): Promise<void>`. Meta keys: `deviceToken`, `catalog`, `soldSinceFetch`.
- Produces, `src/kassa/store/outbox.ts`: `enqueue(item: OutboxItem): Promise<void>`; `pendingCount(): Promise<number>`; `rejectedCount(): Promise<number>`; `type SendResult = { ok: true; results: ItemResult[] } | { ok: false; reason: "offline" | "unauthorized" | "server" }`; `type FlushOutcome = { sent: number; rejected: number; remaining: number; stopped?: "offline" | "unauthorized" | "server" }`; `flush(send: (items: OutboxItem[]) => Promise<SendResult>): Promise<FlushOutcome>`.
- Produces, `src/kassa/store/catalog.ts`: `loadCatalog(): Promise<Catalog | null>`; `saveCatalog(c: Catalog): Promise<void>` (also resets `soldSinceFetch`); `noteSold(lines: { productId: string; qty: number }[]): Promise<void>`; `soldSinceFetch(): Promise<Record<string, number>>`.
- Produces, `src/kassa/store/sync.ts`: `type SyncState = { online: boolean; pending: number; rejected: number; paired: boolean }`; `startSync(onState: (s: SyncState) => void, onCatalog: (c: Catalog) => void): { stop(): void; kick(): void }`. It flushes on `kick()`, on the window `online` event and every 30 seconds; it refreshes the catalog every 30 seconds, after each successful flush and when the page becomes visible, but only while the outbox is empty, so that the stock on the tiles counts every sale exactly once.
- Produces pages: `KassaPage` (route `/`), `PairPage` (route `/koppelen`).

`flush` rules: read up to 50 items in `seq` order and call `send`. On `ok`: delete every item whose result is `accepted` or `duplicate`; move every `rejected` item to the `rejected` store and delete it from the outbox; repeat while items remain. On not `ok`: stop, delete nothing, report the reason. Calls made while a flush runs join that flush.

`KassaPage`: no `deviceToken` → navigate to `/koppelen`. Otherwise render from the cached catalog at once and refresh in the background; with no cache and no network show `Geen verbinding. De kassa heeft één keer internet nodig om te starten.` `onSale` → `enqueue`, `noteSold`, remember the last sale, `kick()`. A 401 from any kassa call sets `paired: false` and keeps the outbox.

Copy. `StatusBadge`: `Online`; `Offline · contant werkt door`; `{n} verkoop wacht op verzending` / `{n} verkopen wachten op verzending`; `{n} verkoop afgekeurd, meld dit aan de penningmeester` / `{n} verkopen afgekeurd, …`; `Kassa is ontkoppeld.
